## Refuted / non-decisions (kept to prevent rejection amnesia)

- **F4 is not a bug.** The update-path `onValidate`-inside-`try` is safe today (non-local return).
  Do not re-raise it as an active defect; PLAN P1.2 hardens it structurally regardless (turns
  safe-by-coincidence into safe-by-structure), which is a separate, accepted motivation.
- **"All CRUD passes through `apiItemProcess`" is false** as a general statement (the stakeholder's
  objection). It is true only of the remote surface. The low-level/service tier is the layer
  *below* `apiItemProcess` and does not pass through it. Verified empirically (downstream SmokeM4)
  and by code trace.
- **After-hooks fire on *attempted* writes, not only successful ones** (review clarification of I2).
  Every engine fires `onAfter{Create|Update|Delete|Upsert}Action` exactly once for any write that
  reaches the driver call, passing `result = false` on failure; only the change-log is success-gated.
  Do **not** "fix" the after-hooks to fire only on success — that is intended (it lets hooks observe
  failures). The earlier KDoc wording that implied success-only was the documentation bug, now
  corrected in `IRepository` KDoc and CONTRACT.md I2.
